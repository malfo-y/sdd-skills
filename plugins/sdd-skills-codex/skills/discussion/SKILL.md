# Discussion

## Goal

사용자와 함께 이번에 답할 질문이나 내릴 결정을 명확히 하고, 필요한 근거·대안·가정을 검토한다. 후속 작업이 배경과 결정 이유를 복원할 수 있도록 `_sdd/discussion/<YYYY-MM-DD>_discussion_<slug>.md`에 요약을 남긴다.

## Acceptance Criteria

- [ ] 이번 토론의 질문·결정과 범위가 명확하고, 사용자 의도에 맞는 검토가 이루어졌다.
- [ ] 결정에 영향을 주는 근거·대안·중요 가정을 검토했으며, 확인한 사실과 사용자 판단·미검증 가정을 구분했다.
- [ ] 결정과 이유, 중요한 미결과 필요한 다음 행동이 요약에 보존되었다.
- [ ] 요약이 Output Contract를 따르고, 종료 상태와 검토하지 못한 범위를 사실대로 표시했다.

정상 종료와 중단·미완료의 구분은 `정리와 종료`를 따른다.

## Boundaries

- 토론은 read-only다. 코드·스펙·설정을 수정하지 않는다. 파일 쓰기는 요약 저장과 호출 환경의 work log 규약에 따른 append로 한정한다.
- 사용자에게 속한 선호·우선순위·수용 가능한 손실을 대신 결정하지 않는다. 이미 주어진 범위·선택·종료 의사는 다시 승인받지 않는다.
- 미검증 주장이나 미결을 확정된 사실·결정으로 바꾸지 않는다. 후속 스킬과 구현은 사용자의 별도 요청으로 실행한다.

## Runtime

이 스킬은 interactive-only이며 질문에는 `request_user_input`을 사용한다. 이를 사용할 수 없으면 토론을 시작하지 않고, 진행 중이었다면 `정리와 종료`의 부분 저장 규칙을 따른다.

선택형 질문에는 정리/종료 선택지를 포함해 총 2–3개 옵션을 사용한다. `Other`는 직접 추가하지 않으며 선택지로 담기 어려운 맥락은 UI의 자유 입력으로 받는다. 질문과 요약은 사용자의 언어를 따르며 별도 저장 언어 요청이 있으면 반영한다.

## Discussion Guidance

아래는 판단 기준이며 고정된 페이즈나 질문 순서가 아니다. 대화에서 이미 확보한 정보는 그대로 활용한다.

### 질문과 범위

이번 토론에서 답할 질문이나 내릴 결정을 짧게 정리한다. 여러 영역을 다루더라도 비교·공통 정책·우선순위처럼 하나의 의사결정이면 함께 다룬다. 독립적인 논의가 섞여 진행하기 어려울 때는 분해와 순서를 제안한다.

다음 질문은 답이 결정·범위·후속 행동을 가장 크게 바꾸는 불확실성에서 고른다. 사용자만 제공할 수 있는 정보가 필요할 때 한 번에 한 가지를 묻는다. 로컬 파일이나 자료로 확인할 사실은 직접 조사한다. 동기·현황·제약·목표는 빠진 중요한 맥락을 찾는 관점으로 사용하며, 이미 확인했거나 관련 없는 항목을 채우기 위한 질문은 만들지 않는다.

### 근거와 대안

토론에 필요한 로컬 맥락을 확인하고, 최신성이나 사실 검증이 필요한 외부 주장은 공식 문서·1차 자료로 확인한다. 이미 확보한 근거가 충분하면 재조사하지 않는다. 수렴 중이거나 빠른 정리를 요청받았더라도 새 주장을 검증한 사실처럼 취급하지 않는다. 조사를 줄여야 하면 판단에 미치는 불확실성을 밝힌다.

선택이 열려 있고 실질적으로 구별되는 대안이 있으면 트레이드오프와 권장안을 이유와 함께 제시한다. 사용자가 방향을 고정했다면 그 선택의 영향과 위험을 검토한다. 기각한 대안은 다시 검토할 필요가 없도록 이유를 보존한다.

유력한 방향의 중요한 약점·숨은 가정·반례를 검토하고 결과를 설명한다. 직접 확인 가능한 가정은 조사와 분석으로 검토할 수 있다. 사용자 판단이 필요한 트레이드오프는 질문한다. 형식적인 비판 질문이나 응답 횟수를 완료 조건으로 삼지 않는다.

새 근거가 기존 결정을 흔들면 해당 결정과 영향받는 후속 행동을 재검토한다. 해소되지 않으면 미결로 남기고 무엇이 더 필요한지 기록한다. 새 근거 없이 같은 주장을 반복하기보다 다른 확인 방법이나 보류를 제안한다.

### 미결과 진행 판단

결정과 이유, 아직 답하지 못한 질문, 필요한 다음 행동을 추적한다. 사용자의 유보가 나오면 지금 구체화할 수 있는 문제인지, 외부 데이터가 필요한지, 다른 결정에 의존하는지 판단한다. 다시 묻는 것은 답을 얻을 가능성이 있고 그 답이 현재 판단을 바꿀 때다.

미결의 분류는 요약 작성 시 맥락에 따라 기록한다. 사용자에게 라벨 선택 자체를 요구하지 않으며, 분류가 후속 처리에 영향을 주고 맥락으로 정할 수 없을 때만 실제 처리 방향을 묻는다. 사용자 지정 분류와 의존 관계를 보존하고 내부 추정을 사용자 결정으로 표시하지 않는다.

논의가 복잡해지거나 사용자가 요청하면 핵심 결정과 남은 쟁점을 짧게 정리한다. 추가 대화로 중요한 불확실성을 줄일 수 있으면 계속하고, 새 정보가 없거나 외부 작업이 선행되어야 하면 미결과 다음 행동을 보여주며 정리를 제안한다. 정해진 라운드 수나 미결 개수로 종료를 결정하지 않는다.

### 정리와 종료

사용자가 정리를 요청하거나 종료를 선택하면 요약을 저장한다. 더 논의하겠다고 선택하면 계속한다. 종료 의사가 아직 없으면 정리를 제안해 사용자의 선택을 받는다. 무응답을 종료 동의로 간주하지 않는다.

합의한 범위에서 검토 가능한 내용을 다루고 사용자가 종료했다면 정상 종료다. 외부 데이터 대기나 의도적 보류가 남아도 미결·이유·다음 행동을 기록하여 정상 종료할 수 있다. 주제를 정하지 못했거나, 사용자 중단·응답 단절·도구 실패로 합의한 검토를 마치지 못했다면 확보한 맥락을 `중단·미완료`로 저장하고 검토하지 못한 범위를 표시한다. 부분 저장을 위해 질문을 재개하지 않는다. 저장할 맥락이 없으면 산출물 없이 중단 사유만 보고한다.

## Output Contract

요약 작성 직전에 `references/summary-template.md`를 읽고 fenced template을 verbatim 출발 구조로 사용한다. 필수 섹션·표 열은 보존하고, 슬롯 치환·반복 행·조건부 섹션·표시 언어는 템플릿이 허용한 방식으로만 바꾼다.

파일명은 `<YYYY-MM-DD>_discussion_<slug>.md`이며 slug는 소문자 영문 snake_case, 최대 50자다. `_sdd/discussion/`가 없으면 생성한다. 같은 토론의 기존 요약을 갱신하는 경우 외에는 동명 파일을 덮어쓰지 않고 구별되는 slug를 사용한다.

저장 후 주요 결정·남은 미결과 파일 링크를 짧게 보고한다. 전체 요약의 채팅 출력은 사용자가 요청할 때 제공한다.

## References

- `references/summary-template.md`: 결과물 형식의 단일 소스. 요약 작성 시 필수로 읽는다.
- `references/discussion-question-guide.md`: 질문 표현을 고르는 데 도움이 필요할 때 읽는 예시. 추가 실행 규칙은 없다.
- `examples/sample-discussion-session.md`: 사람을 위한 세션·요약 예시. 실행 시 필수 읽기 대상이 아니다.

## Recovery

범위를 정할 수 없으면 빠진 핵심 정보를 묻고, 같은 확인이 진전 없이 반복되면 현재 한계와 재개에 필요한 정보를 밝힌다. 조사 실패는 실패 사실과 남은 불확실성을 표시하고, 확보한 근거로 가능한 검토를 계속한다. 필수 질문 도구의 실패·부재는 Runtime을 따른다.

## Final Check

선택한 종료 경로의 AC와 요약을 한 번 점검한다. 현재 보완 가능한 기록 누락은 고치고, 검토하지 못한 내용은 미충족 사유로 남긴다. 과거 라운드나 사용자 응답을 만들어 채우지 않는다.
