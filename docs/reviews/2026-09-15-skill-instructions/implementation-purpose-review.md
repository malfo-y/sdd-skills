## Findings

### IM-P01 — 검증 의무의 근거를 보편적 사실로 과장한다 [설명 정확성 수정 권고]

- **위치 / 근거:** 117행: “변이 확인 없는 델타 테스트는 코드를 보고 짜맞춘 무조건 통과 테스트다.”
- **문제:** 변이 확인을 하지 않았다는 사실만으로 테스트가 무조건 통과한다고 결론낼 수 없다. 예를 들어 정해진 입력의 정확한 출력을 비교하는 assertion은 구현이 달라지면 실패할 수 있으며, 변이 실행 여부와 이 성질은 별개다. 이 저장소가 그 판별력을 실제로 확인하도록 요구하는 정책은 여전히 유효하다.
- **권고:** “델타 테스트는 변이 확인으로 판별력을 확인한 뒤 검증 증거로 인정한다”처럼 repo가 요구하는 증거 기준으로 쓴다. 변이 확인 절차·실패 관찰·복구 후 GREEN 의무는 그대로 둔다.
- **유지 / 손실 위험:** 검증되지 않은 테스트를 근거로 충족을 선언하지 않는 경계. 설명을 고치며 변이 의무까지 선택 사항으로 만들지 않는다.
- **검증 시나리오:** 문장 변경 전후 델타 테스트의 완료 판정과 필요한 증거는 동일해야 한다. 이는 정책 변경이 아닌 근거 설명의 정확성 수정이다.

### IM-P02 — resume 기록을 한 행에 과도하게 고정한다 [설계 변경 후보]

- **위치 / 근거:** 49–64행은 모든 실행에서 ledger를 만들고 task당 한 행에 상태·triage·RED/GREEN·오류 횟수·계획 이탈·발견·범위 밖 수정·델타 처리를 넣는다. 135행은 마감 표를 ledger에 쓰고 같은 표를 채팅에도 노출한다.
- **문제 상황:** 한 task에서 여러 발견과 계약 수정이 생기면 한 행 규칙이 기록을 조밀하게 만들며, 큰 AC 표는 채팅에도 반복된다. 반면 실제 재개를 위해 RED 관찰 여부·범위·다음 행동을 남기는 목적은 분명하다.
- **권고:** ledger와 네 상태는 유지하되, 필수 resume 정보와 발생했을 때만 필요한 예외 기록을 구분한다. 긴 예외는 task 식별자가 붙은 짧은 블록을 허용하는 안을 비교한다. 채팅은 문제·변경된 증거·문서 링크 중심으로 줄일 수 있는지 별도로 검토한다. 외부 goal 평가자가 transcript 증거를 요구하는 경로에서는 그 요구를 충족해야 한다.
- **유지 / 손실 위험:** 최초 dirty 범위, RED 관찰 이력, 계약 오류 횟수, 계획 이탈의 이유, 상태 갱신 시점과 fresh 재판정은 보존한다. 기록 선택성 때문에 compact 후 이미 한 일을 반복하거나 실패를 통과로 복원하면 안 된다.
- **검증 시나리오:** RED 직후, GREEN 후 델타 미완료, gate fix 도중의 세 시점에서 새 문맥이 ledger만으로 안전한 다음 행동을 정하는지 비교한다. ledger 실사용이 없다는 증거는 확보하지 않았으므로 제거를 권하지 않는다.

### IM-P03 — gate 1과 gate 2의 같은 fix 정책을 반복한다 [표현 정리 후보]

- **위치 / 근거:** 마감 140–147행. gate 1과 gate 2가 같은 Critical/High/Medium 반영과 Low 정책을 사용하고, 각 fix 검증은 공통 규칙으로 이어진다.
- **권고:** 첫 호출 필수·추가 호출 조건·호출 상한을 한 곳에서 정하고, 각 호출의 finding 반영→델타→회귀→증거 갱신 규칙을 한 번 정의한다. 두 번째 호출 뒤에만 필요한 finding별 표적 검증과 추가 수동 리뷰 권고는 명시적으로 남긴다. 새 orchestrator·별도 gate 스킬을 만들지 않는다.
- **유지 / 손실 위험:** fix 전 raw 수치, dedup 없음, C+H≥3 또는 M≥5, Low 렌즈별 차이, 최대 2회, producer 소유권, 사용자 대기 없이 fix 복귀. 공통화하다 예외 조건의 적용 범위가 달라지는 것이 주 위험이다.
- **검증 시나리오:** 첫 gate 임계 미달/도달, correctness Low와 simplicity Low, 문서만 고친 fix, gate 2에서도 임계 도달을 각각 대조한다. 기존 실행 순서·재검증·종료 결과가 동일해야 한다.

## 유지할 계약과 후속 범위

test-free·read-only 검증 경로, 의미 있는 RED, 테스트 약화 금지, 실제 diff의 미검증 동작 점검, 불필요한 코드 삭제 후 재검증, 증거 없는 MET 금지, slow/checkpoint 경계, 단일 작성자는 유지한다. 절차가 번거롭다는 이유만으로 삭제할 근거가 없다.

고정 재리뷰 임계의 규모 적응과 ledger의 실사용 관측은 이미 global spec의 후속 과제다. 이번에 새로운 발견으로 중복 등록하거나 임의 변경하지 않는다. IM-P02를 적용할 때는 evidence의 채팅 소비자와 resume 테스트를 먼저 확인해야 한다. 수정 범위는 양쪽 본문·관련 global spec 설명과 ledger 소비 계약이며, 실제 모델의 구현 품질이나 처리 시간 개선은 미검증이다.
