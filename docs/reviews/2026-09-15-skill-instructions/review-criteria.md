# 스킬 지시 리뷰 기준

- 요청: 모든 저장소 스킬에 동일한 지시 리뷰를 병렬 적용하고 스킬별 결과를 남긴다.
- 날짜: 2026-09-15 KST. 모델: gpt-6-astra.
- 기준 커밋: `be6c5a1f014b3e37d386127966b0bb6de3549587`.
- 범위: `.claude/skills/*/SKILL.md`와 `plugins/sdd-skills-codex/skills/*/SKILL.md`의 합집합. 같은 이름의 런타임 짝은 한 문서로 리뷰한다. 직접 참조 문서는 해당 finding 판정에 필요한 범위에서 읽는다.
- 작업 종류: 지시·계약의 정적 리뷰. 대상 스킬 실행, 설치본 변경, 코드·스킬·global spec 수정, commit/push는 하지 않는다. 문면상 위험과 실제 실행 관측을 혼동하지 않는다.

## 여섯 가지 기준

1. 적용 조건: 항상·반드시·중단 지시가 발동하는 조건과 범위가 명확한가.
2. 충돌과 우선순위: 동일 상황에서 다른 행동을 요구하는가. 사용자 요청·사전 승인·단계 규칙 사이 우선순위가 명확한가.
3. 확인·승인 경계: 이미 승인된 행동을 다시 묻거나 결과에 영향 없는 선택 때문에 멈추는가. 파괴적 행동의 필요한 승인 경계는 보존한다.
4. 중복과 소유권: 본문 내부·reference·위임 스킬과 규칙이나 실제 수행 의무가 중복되는가. 배포 mirror는 그 자체로 중복 결함이 아니다.
5. 완료·복구 조건: 완료 판정 가능성, 복구 가능한 누락과 과거 경계 위반 구분, 재시도 종료 조건이 있는가.
6. 절차의 필요성: 고정 단계·문서·가설 수·도구 호출이 목적에 필요한가. 길이나 강제어 개수만으로 finding을 만들지 않는다.

## 판정 및 증거

- **수정 필요**: 인용한 문구와 구체적인 입력/상황에서 모순·불필요한 중단·중복 실행 경로를 설명할 수 있다. 실제 모델 행동이 재현되었다는 뜻은 아니다.
- **정리 후보**: 계약과 결과를 유지하면서 단순화하는 동등한 문구를 제시할 수 있다. 취향과 측정하지 않은 비용 절감을 결함처럼 단정하지 않는다.
- **실행 검증 필요**: 위험 가설은 있으나 실제 모델 실행 관측이 있어야 판정할 수 있다.
- 근거가 없으면 **수정 필요 없음**. finding 최소/최대 개수 할당 없음. 검토하지 못한 직접 의존성은 미검토로 적는다.
- finding마다 ID, 분류, 기준 번호, 적용 runtime, 상대 파일 링크와 줄 번호, 짧은 정확한 원문, 문제 상황, 예상 영향, 최소 수정안, 유지할 계약, 소유자, 검증 상태를 기록한다.
- spec에 박힌 설계 변경을 단순 문구 수정으로 포장하지 않는다. 필요한 경우 `spec 결정 필요`를 표시한다.
- 직접 런타임을 조사하지 않았으면 API/모델/기능이 없다고 단정하지 않는다. 도구 차이와 lifecycle 예시는 이번 활성 schema와 영구 지원 여부를 구분한다.

## 보존할 저장소 계약

판단의 단일 소스는 [global spec](../../../_sdd/spec/main.md)이며 아래는 읽기 안내다.

- global spec은 thin truth, 변경 실행 정보는 temporary artifacts. evidence 없는 완료 승격 금지.
- AC 섹션 및 종료 전 자체 검증 의무. 원본 보존·파괴적 동작 승인·권한 경계.
- producer가 gate를 소유: feature-draft→plan-review, implementation→implementation-review. 호출자는 중복 gate/fix 금지. gate 호출당 단일 pass, 고정 임계와 최대 2회는 현행 설계다.
- plan-review 메인 직접 실행, implementation 직접 작성, 필요한 simplicity leaf dispatch 구조는 현행 설계다. 이 리뷰에서 피리뷰 스킬을 실제 호출하지 않는다.
- 30초 표적 check timeout, 10초 테스트 분리 기준, fast-only 마감, runtime-local reference와 mirror 배포 계약.
- goal-init / sdd-autopilot의 setup-only·native goal 미발동·status 미조회·5단계·4파일 계약.
- hook 설치·사용자 trust·기존 설정 보존, snapshot 원본 불변, verified/planned 분리.
- skill authoring norms는 참고 기준이며 모델별 성능·행동 효과는 실측 없이 주장하지 않는다.

## 리뷰어 작업 및 출력 계약

사용자는 병렬 리뷰와 문서 저장을 승인했다. 각 leaf는 지정된 스킬 문서 **하나만** 쓴다. skill/ref/global spec은 읽기만, 다른 리포트·인덱스·work log·git branch/index에는 쓰지 않는다. subagent 재spawn 금지. 메인 작성자가 전체 work log를 기록한다. 파일 권한 0644.

1. AGENTS.md → 관련 global spec → env → 이 기준 → 지정 스킬 runtime 짝과 필요한 직접 reference를 읽는다. 길면 나눠 읽고 잘린 출력에 의존하지 않는다.
2. finding을 실제 줄·원문과 대조한다. 필요한 직접 이웃 계약만 확인한다. 과거 로그는 원인 추적에 필요할 때만 읽는다.
3. 지정된 `<skill>.md`에 아래 형식으로 한국어 보고서를 쓴다. 문서 안에서는 사용자 호칭 불필요. 메인에 보낼 최종 요약은 문서 경로·분류별 개수·핵심 finding·cross-skill 소유자만.

```markdown
# <skill> 지시 리뷰

- 날짜: 2026-09-15 KST
- 모델: gpt-6-astra
- 기준 커밋: be6c5a1f014b3e37d386127966b0bb6de3549587
- 상태: 정적 리뷰 완료 / 제안 미적용 / 동작 미검증
- 대상: [Claude](../../../.claude/skills/<skill>/SKILL.md), [Codex](../../../plugins/sdd-skills-codex/skills/<skill>/SKILL.md) 또는 해당 runtime 없음
- 판정 요약: 수정 필요 N / 정리 후보 N / 실행 검증 필요 N

## 역할과 유지할 계약
간결한 설명.

## 기준별 판정
6개 기준을 각각 한 행으로 표시. finding ID 또는 수정 필요 없음과 근거.

## Findings
### <skill>-01 — <제목> [분류]
위 증거 계약의 필드를 간결하게 기록. 문제가 없으면 근거와 함께 수정 필요 없음.

## 런타임 차이와 의존성
정당한 차이와 소유자 간 연결. 읽은 reference 목록, 미검토 범위.

## 권장 처리 순서와 검증
가장 작은 후속 변경과 구체적인 실행 확인 방법. 이번 리뷰에서는 실행하지 않았음을 명시.
```

문서 링크는 이 디렉터리 기준 `../../../`가 repo root다. GitHub 링크에는 줄 번호를 별도 텍스트로 적는다(로컬 상대 링크에 `:줄`을 붙이지 않는다). 전체 요약과 중복 통합은 메인 작성자가 수행한다.
