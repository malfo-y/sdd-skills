## Findings

### GI-P01 — 대화의 순서까지 완료 계약으로 고정한다 [설계 변경 후보]

- **위치 / 근거:** 본문 55행은 5단계 순서와 Gate 전이를 고정한다. 66·76·94·105·117행에 각 전이가 있고, AC6도 SDD preset에서 동일 단계를 요구한다.
- **문제 상황:** 사용자가 목표·검증 명령·승인 범위·선택한 접근을 이미 제공해도 단계 충족 여부를 따져야 한다. 모든 Gate가 별도 사용자 질문을 요구한다는 뜻은 아니다. 불필요한 것은 매번 같은 대화 진행 경로를 정상 완료 조건으로 삼는 부분이다.
- **권고:** 필수 확인 항목을 목표 적합성·판정 가능한 조건·권한 범위·실행 가능한 검증·완성된 하네스로 고정한다. 대화 순서와 이미 제공된 정보의 수집은 상황에 맡긴다. 미해결 정보가 결과를 바꿀 때만 질문한다.
- **유지 / 손실 위험:** 조건 확정 전 실행을 시작하지 않는 경계와 사용자만 정할 수 있는 승인은 유지한다. 순서 완화로 권한이나 검증 누락이 생길 수 있으므로 완료 점검은 없애지 않는다.
- **검증 시나리오:** 완전한 입력과 목표만 있는 입력을 각각 처리한다. 전자는 재수집 없이 완성하고, 후자는 중요한 누락을 확인해야 한다. 질문 수보다 최종 조건·권한의 정확성을 먼저 평가한다.

### GI-P02 — 모든 목표에 가설 2개 이상을 요구한다 [설계 변경 후보]

- **위치 / 근거:** AC2(23행), Key Principles(48행), Step 2(68–76행). 후보가 없으면 사용자에게 요청하고, pending 가설 2개를 확보해야 다음 단계로 간다. 템플릿의 Generic payload는 가설 큐를 실행하지만 SDD payload는 미충족 목표의 가장 작은 feature를 고르며 가설을 참고로만 쓴다.
- **문제 상황:** 사용자가 확정한 마이그레이션 계획을 검증하며 완료하려는 멀티턴 작업에서도 두 번째 접근을 만들어야 한다. 원인 탐색과 확정 계획 실행의 차이를 최소 개수 규칙이 반영하지 않는다.
- **권고:** 해결 경로나 원인이 열려 있으면 구별되는 가설과 검증법을 비교한다. 경로가 확정돼 있으면 선택된 접근과 남은 불확실성만 기록할 수 있게 한다. Generic 큐에는 실행 가능한 다음 시도가 있어야 하지만, 대안 개수는 완료조건에서 제외하는 안을 검토한다.
- **유지 / 손실 위험:** 무비판적 단일안 고착을 막는 검토는 유지한다. 가설을 선택 사항으로 바꾼 뒤 탐색 과제에서도 아무 대안 없이 진행하는지 확인해야 한다.
- **검증 시나리오:** 원인 불명 flaky test와 확정된 API 교체 계획을 비교한다. 전자는 경쟁 가설이 검증 가능해야 하고, 후자는 숫자를 채우는 대안을 만들지 않아야 한다.

### GI-P03 — 같은 판정 기준을 여러 절에서 다시 정의한다 [표현 정리 후보]

- **위치 / 근거:** 평가자 자족성과 길이 제한은 AC3(24), Hard Rule 2(32), Key Principles(46), self-check(88–94)에 겹친다. 능동 발산도 48·70–76행에 재서술된다.
- **권고:** 조건 self-check와 발산 적용 기준은 각각 소비 지점 한 곳에서 정의하고, AC·도입부에는 짧은 참조만 남긴다. GI-P01·02의 정책 변경과 별도로 적용 가능한 정리다.
- **유지 / 손실 위험:** 조건 전문의 화면 출력은 사용자가 실제로 검토하고 활성화하는 결과물 인터페이스다. 단순 중복으로 삭제하지 않는다. 실행 시점이 다른 템플릿 안의 런타임 지시도 본문과 중복이라는 이유만으로 제거하지 않는다.
- **검증 시나리오:** 미검증 조건, 길이 제한 초과, 활성화 요청 없는 setup을 대조해 기존 완료·중단 판정이 그대로인지 확인한다.

## 유지할 계약과 후속 범위

setup-only와 기존 goal 상태 보존, 명시적 권한 범위, 조건/검증 레시피/Loop Protocol 분리, 판정 약화 변경의 승인, 실제 증거와 미완료 상태 구분은 유지한다. 특히 2026-08-14 이력은 검증 세부사항을 조건에 과도하게 넣어 goal 재설정이 필요했던 사례를 기록한다. 조건을 다시 상세 실행 절차로 채우면 안 된다.

수정 시 양쪽 본문·하네스 템플릿·sample session, sdd-autopilot의 위임 설명, global spec의 5단계 재사용 결정을 함께 확인한다. 이번 제안은 기존 결정을 바꾸는 승인이 아니다. 실사용 개선은 같은 종류의 입력에서 권한·판정 정확성·가설 품질·불필요한 질문을 관측한 뒤 판단한다.
