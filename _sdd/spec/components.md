## Delivery & Review

| Component | Purpose | Why | Primary Source | Notes |
|-----------|---------|-----|----------------|-------|
| `plan-review` | 구현 전 계획을 findings-first로 감사한다 | 요청↔계획 불일치, 과잉 설계, 숨은 결정, 약한 검증 기준이 구현으로 전파되기 전에 드러낸다 | `.claude/agents/plan-review-agent.md`<br>`.claude/agents/plan-context-gatherer.md`<br>`.claude/skills/plan-review/SKILL.md`<br>`.codex/agents/plan-review-agent.toml`<br>`.codex/agents/plan-context-gatherer.toml`<br>`.codex/skills/plan-review/SKILL.md` | orchestrator(skill) + gather 병렬 fan-out + 판정 단일 dispatch — SKILL이 draft 1회 read로 Target Files를 그룹(3~5파일, 최대 ~6그룹)으로 묶어 수집 전용 `plan-context-gatherer`를 병렬 dispatch하고(digest는 `_sdd/pipeline/plan_review_gather/<draft-slug>/`에 verbatim 발췌·파일당 ~150줄 상한·리뷰 후 미삭제), `plan-review-agent`를 **1회 dispatch**해(digest 경로만 전달) 경량 반환을 정리해 relay한다(Blocker Status 보존, finding 반영은 호출자 소관). 판정 agent는 digest를 병렬 Read 배치로 흡수하되 Critical/High evidence는 원본 residual read로 확정하고, digest 미제공 시 자체 read로 동작한다(하위 호환; degrade — Target Files 공백/전부 실패 시 단일 dispatch, 일부 실패 시 성공 digest만). 2026-08-13에 실측 ∥ 판단 2-렌즈 분해를 철회하고 단일 dispatch로 복귀했다(근거는 main.md — 벽시계 max를 항상 실측 렌즈가 결정). codex SKILL은 schema-selected lifecycle과 framed payload 문법을 Codex Runtime Adapter 블록이 단일 소스로 보유한다. 각 호출에서 feature draft를 단일 패스로 리뷰하고 경량 반환으로만 응답한다(리포트 파일·reviewer 내부 re-review 없음, tools에 Write 없음). 호출 주체는 `feature-draft`다(자기 품질 게이트로 기본 1회, gate 1의 fix 전 raw finding이 임계값이면 최대 2회 호출; autopilot은 호출자가 아니다). rubric은 5-smell 단일 표면이다 — `Requirement Fit`(요청·spec delta ↔ task/AC 정합성, 누락·과잉 양방향) / `Task Boundary Drift` / `Hidden Decision`(Open Questions 항목별 결정·확인 필요 여부, 남은 숨은 가정 — 2026-08-12에 producer 슬롯 없는 `가정·대안·확신도` 술어와 Step 2 `decision markers` 항목을 삭제) / `Over-engineering`(중복 구현·과한 추상화·단일 사용처·정당화 없는 `[C]` 신규 파일·draft 내부 재서술) / `Verification Weakness`(AC evidence·Target Files 실측·content anchor). 규모 판정 검사는 없다(분할 판정은 producer 단독 — main.md guardrail). Hard Rules는 rubric과 겹치지 않는 **작성 룰만** 보유하고(read-only·출력 언어·Blocker Policy·최소 recommendation·producer 계약 재서술 금지) 검사 술어는 rubric이 단독 소유하며, 자체 검증 AC는 3개(smell 전수 점검·finding 필드·산출물 하나+비열거)다. Critical/High finding은 implementation blocker로 표시한다. recommendation은 cited evidence를 해소하는 smallest change 규칙 하나로 제한한다. finding 반영과 호출별 검증은 작성자인 producer가 소유하고, 리뷰 대상 draft가 없으면 안내 1줄만 반환한다. supporting context 읽기에는 입력 상한이 걸려 있다(렌즈 한정 시 실측 렌즈 소유)(Claim Manifest 계약은 도입 당일 철회 — main.md 리뷰 읽기 다이어트). 판정에 필요한 최소한만 읽는다 — `Glob`·`Grep`으로 닫히는 판정은 `Read`하지 않고, `Read`를 앞선 도구 호출과 함께 미리 당겨 부르지도 않으며(선행 호출이 조기 종료를 무력화한다), 그래도 근거가 부족하면 그 smell의 finding을 만들지 않고 읽기를 확장하지 않는다. 이 읽기 규칙과 tool call 배칭의 관계는 agent Step 3이 단일 소유자다(Input 절·Error Handling 문장은 포인터만이고 Hard Rule에 복제하지 않아 판정 주체를 한 곳으로 유지한다). 반환은 Blocker Status·Findings 2항목이 전부다 |

Step 2 검증 방법 확정 사용자 확인 게이트를 메인 루프가 직접 수행한다(subagent는 실행 중 대화 불가라 skill 전환으로 비로소 작동). 생성 산출물은 6파일(`config.sh`/`PROMPT.md`/`run.sh`/`state.md`/`CHECKS.md`/`decisions.md`)이고 `config.sh` 고정 루프 제어 변수는 4개다(`LLM_TIMEOUT_SECONDS`·`MAX_LLM_FAILURES`·`MAX_RUNTIME_MINUTES` 기본 720분·실행 1회 기준·soft 판정·`MAX_ITERATIONS` 기본 200·누적 backstop). 상한 도달 시 `phase:`를 보존한 채 `notes:`만 기록하고 `exit 1`한다(재개 경로 유지). iteration 순서는 진입 DONE 가드 → 상한 판정 → LLM → state 검증 → action.sh 실행/archive → 사후 DONE 판정으로 고정돼 DONE 전환 iteration의 action도 실행·archive된다. init 시점 자체검증은 `bash -n` + 미충전 `<...>` 슬롯 0이며 검사 범위의 단일 소스는 Step 8이다. 진입 경계 — 세션 수명 초과·무인 격리 실행·iteration마다 fresh context가 필요할 때만 ralph이고, 세션 안에서 닫히는 반복은 `investigate`(단발 디버깅)와 네이티브 `/goal`(셋업은 `goal-init`)로 보낸다. codex는 run.sh LLM 호출·Security Notice의 CLI flag delta(`--dangerously-bypass-approvals-and-sandbox`)를 보존한다 |
