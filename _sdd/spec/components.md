Step 2 검증 방법 확정 게이트를 메인 루프가 직접 수행하며, 핵심 정보가 미확정일 때만 사용자에게 질문한다(subagent는 실행 중 대화 불가라 skill 전환으로 비로소 작동). 생성 산출물은 7파일(`config.sh`/`verify.sh`/`PROMPT.md`/`run.sh`/`state.md`/`CHECKS.md`/`decisions.md`)이고 `config.sh` 고정 루프 제어 변수는 4개다(`LLM_TIMEOUT_SECONDS`·`MAX_LLM_FAILURES`·`MAX_RUNTIME_MINUTES` 기본 720분·실행 1회 기준·soft 판정·`MAX_ITERATIONS` 기본 200·누적 backstop). `verify.sh`는 Step 2 hard gate에서 확정한 검증 명령을 init이 굳힌 고정 실행 파일로 루프 성공 판정의 단일 소스다(exit 0 = 충족, 루프 LLM 편집 금지). 상한 도달 시 `phase:`를 보존한 채 `notes:`만 기록하고 `exit 1`한다(재개 경로 유지). reset은 lock 획득 뒤 수행하고, 실패한 CLI 턴은 state 복원·미확정 action 삭제 후 재시도 상한을 따른다. 정상 iteration 순서는 진입 DONE 가드 → 상한 판정 → LLM → state 검증 → action.sh 실행/archive → 사후 DONE 게이트로 고정돼 DONE 전환 iteration의 action도 실행·archive된다. DONE 게이트 계약(2026-08-17, 자가 성공 선언 방지): `final_report.md`가 없거나 `Final status:`가 없으면 reject, `Final status: PASS` 주장이면 추가로 `verify.sh` exit 0을 요구하고, reject 시 `ADJUST_PHASE`(기본 ADJUSTING, 시작 시 `VALID_PHASES` 멤버십 검증) phase로 복귀시켜 `notes:`에 사유를 남긴다 — STUCK/FAIL 등 에스컬레이션 DONE은 verify 없이 수용하되 모든 DONE 경로가 final_report를 남겨야 한다. PROMPT.md 템플릿은 Success Criteria·Escalation 섹션·`verify.sh`를 self-correction 편집 금지 구역으로 선언하고(기준이 틀렸다 판단되면 수정 대신 STUCK 에스컬레이션), 장기 실행 in-run 조기 종료 가드와 `_sdd/` 수정 금지를 담는다. init 시점 자체검증은 `bash -n`(run.sh·config.sh·verify.sh) + 미충전 `<...>` 슬롯 0이며 검사 범위의 단일 소스는 Step 8이다. 진입 경계 — 세션 수명 초과·무인 격리 실행·iteration마다 fresh context가 필요할 때만 ralph이고, 세션 안에서 닫히는 반복은 `investigate`(단발 디버깅)와 네이티브 `/goal`(셋업은 `goal-init`)로 보낸다. codex는 run.sh LLM 호출·Security Notice의 CLI flag delta(`--dangerously-bypass-approvals-and-sandbox`)를 보존한다 |
| `git` | 변경을 의미 단위로 정리해 커밋/브랜치 작업을 돕는다 | AI가 만든 변경을 의도 단위로 정리해야 한다 | `.claude/skills/git/SKILL.md` | Claude Code 전용. references 없이 SKILL.md 하나다. 승인은 현재 대화 또는 활성 goal 하네스 `goal.md`의 해당 행동별 사전 승인으로 충족될 수 있다 — 계획 표시는 불변, "항상 확인" 목록은 위임과 무관 |
