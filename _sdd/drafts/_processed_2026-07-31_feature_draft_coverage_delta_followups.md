# Part 1: Spec Delta

## Change Summary

머지된 커버리지 델타(spec 4.6.17)를 사후 감사한 결과, 신설 §4가 만든 정합 갭 4건이 나왔다. 규칙의 방향은 유지하고 문면만 고친다.

- **새 contract**: 소유권을 표면 역할로 가른다 — §4는 **적용 대상**(fix diff에도 적용된다)만 소유하고, **순서**(fix → 델타 → 회귀 재실행)는 순서를 집행하는 **마감 §3이 소유**한다. §4 말미의 순서 절을 마감 §3으로 **이동**한다(추가가 아니라 이동 — 서술 지점은 계속 1곳). 지금은 순서가 §4에만 있어 마감을 순차 집행하는 메인 루프가 §4로 되돌아갈 트리거가 없고, 포인터를 덧붙이는 방식이면 §4·마감 §3·spec 세 곳에 같은 순서 명제가 남는다.
- **전파 대상**: `_sdd/spec/main.md`의 **마감 순서 항**(현재 `회귀 1회 → 증거 테이블 → 게이트 1회 … → 마감 요약` 열거)과 `_sdd/spec/components.md`의 `implementation` 행 **두 문구** — (1) `(c)` 기준선을 `(c) 근거가 덮지 못하는 동작`으로 적은 부분(폐기된 척도), (2) 마감 계약 열거에 델타 선행 단계가 없는 부분 — 이 갱신 대상이다. `decision_log.md`의 같은 표현은 append-only 이력이라 수정 대상이 아니고 신규 entry로 갈음한다.
- **새 contract**: 델타 항목을 **삭제한 경우 그 task의 테스트/check를 다시 실행해 통과를 재확인하고 출력을 갱신 캡처**한다. 지금은 GREEN 증거가 삭제 **이전** 시점 출력이라, 삭제로 GREEN이 깨져도 증거 테이블은 통과 상태로 남는다. 안전망인 마감 회귀는 "전체 suite가 있으면"이라 조건부이고 이 repo가 다수 다루는 (b) structural-check task에는 상시 suite가 없다. 테스트 **추가** 경로는 변이 확인으로 판별력을 강제하는데 **삭제** 경로만 무검증으로 열려 있던 비대칭을 닫는다.
- §4 첫 문단이 6개 의무를 한 산문 블록에 압축하고 있어, 형제 절(§2 RED·§3 GREEN)처럼 주 지시문 + 부속 규칙 불릿 형태로 재배치한다. **문장 삭제 없이 배치만 동형화**한다.
- §4의 `(c)` task 예외절이 정의되지 않은 척도를 도입한다 — "`(c)` 근거가 덮지 못하는 동작"에서 `(c) 근거`는 §1에서 **분류 근거 1줄**로 정의돼 커버리지 척도가 아니다. 실제 산출은 일반 규칙과 같은 곳(도달 테스트 0개 → diff 동작 전량)으로 합류한다. 이 절이 실제로 막는 오해는 "테스트가 없으니 이 단계는 N/A"이므로 그 목적만 남기고 미정의 척도를 버린다.

## Scope

- **In**: `.claude`·`.codex` `skills/implementation/SKILL.md` 미러 2벌 — §4 첫 문단 재배치, `(c)` 예외절 재작성, 삭제 경로 재검증 1구, §4 말미 순서 절을 마감 §3으로 이동.
- **Out**:
  - §4의 규칙 **내용** 변경 없음 — 4건 모두 정합·형태 정정이고 새 의무는 삭제 경로 재검증 1건뿐이다.
  - 증거 테이블 스키마 무변경. 델타 행의 `AC` 열 표기 관례는 여전히 미정으로 둔다(첫 실사용에서 굳히는 기존 계획 유지).
  - 변이 확인·무출력·§5 override 조항 무변경.
  - reviewer agent·배칭 Hard Rule 무관.

# Part 2: Tasks

### Task 1: §4 첫 문단을 주 지시문 + 부속 불릿으로 재배치하고 `(c)` 예외절을 고친다

형제 절과 형태를 맞추고, 미정의 척도를 제거한다. 두 편집이 같은 문단에 있어 한 task로 묶는다.

**Contracts**:
- 재배치는 **문장 삭제 없이 배치만** 바꾼다 — diff 실행 지시(동사형)·기준점·hunk 한정·열거 기준·근거 negative·전형적 델타 예시가 모두 남는다.
- `(c)` 예외절은 "`(c)` 근거가 덮지 못하는 동작" 표현을 버리고, 막으려는 오해("테스트가 없으니 이 단계는 N/A")를 직접 부정하는 형태로 쓴다.

**Acceptance Criteria**:
- [ ] AC1: §4 첫 문단 블록에서 부속 규칙이 **각각 한 줄**로 분리된다 — 앵커 `기준점은 이번 task 시작 시점` / `hunk로 한정` / `도달하지 않는 동작을 열거` / `분기·경계값·에러 경로`가 각각 `^- `로 시작하는 줄에 있다(주 지시문 `실제로 실행해 읽는다`는 불릿 밖). 개수만 세지 않는다.
- [ ] AC2: 재배치 전후로 §4의 다음 6개 앵커가 모두 보존된다 — `실제로 실행해 읽는다` / `기준점은 이번 task 시작 시점` / `hunk로 한정` / `도달하지 않는 동작을 열거` / `기억이나 AC 재독이 아니다` / `분기·경계값·에러 경로`. 하나라도 없으면 미충족.
- [ ] AC3: `(c) 근거가 덮지 못하는 동작` 표현이 두 미러 어디에도 없고, 대체 문장이 리터럴 `건너뛰지 않는다`를 포함하며 **열거 기준까지 담는다** — 도달 테스트가 0개이므로 diff 동작 전량이 열거 대상이라는 취지가 문면에 있어야 한다. 오해 부정만 남기면 (c) 실행자가 열거 기준을 문면에서 얻지 못하는 순손실이 생기므로 미충족이다.
- [ ] AC4: 두 미러 `diff` exit 0.

### Task 2: 삭제 경로에 재검증 의무를 추가한다

"삭제가 1순위" 지시 뒤에 삭제 후 재실행 의무를 붙여, 증거 테이블에 싣는 GREEN 증거를 삭제 **이후** 출력으로 고정한다.

**Contracts**: 새 문장의 앵커를 고정한다 — `(a)/(b) task는` + `다시 실행해 통과를 재확인`. **적용 범위를 (a)/(b)로 박는다** — (c)에는 실행할 테스트/check가 없어 무범위로 두면 공허한 의무가 되고, 이 draft가 고치려는 `(c)` 미정의 적용 결함을 새 조항에 다시 심는 셈이다.

**Acceptance Criteria**:
- [ ] AC1: `삭제가 1순위다` 문단에 리터럴 `다시 실행해 통과를 재확인`이 있고, 그 문장이 **(a)/(b)로 범위를 한정**한다(grep + 문장 인용 판정).
- [ ] AC2: 그 문장에서 (c)에 별도 재실행 의무가 생기지 않음이 읽힌다 — (c)를 무조건 포함하는 표현이면 미충족.
- [ ] AC3: 두 미러 `diff` exit 0.

### Task 3: 순서 절을 §4에서 마감 §3으로 이동한다

§4는 적용 대상만 소유하고, 순서는 순서를 집행하는 마감 §3이 소유한다. **추가가 아니라 이동**이라 서술 지점은 계속 1곳이다.

**Contracts**:
- §4 말미의 `적용은 fix 직후이고, 마감의 회귀 재실행은 델타 처리까지 끝낸 뒤 1회 돈다`를 **삭제**하고, 같은 명제를 마감 §3의 fix 불릿에 리터럴 앵커 `§4 커버리지 델타`와 함께 쓴다.
- §4에 남는 것은 적용 대상 문장(`fix diff에 적용한다` + 그 근거)뿐이다. 마감 §3에 §4 고유 문장(`fix 산출물은 AC가 정해진 뒤에`)을 복제하지 않는다.

**Acceptance Criteria**:
- [ ] AC1: 마감 §3 안에 리터럴 `§4 커버리지 델타`가 있고, 그 문장이 fix → 델타 → 회귀 재실행 순서를 드러낸다.
- [ ] AC2: §4에 순서 명제가 **남아 있지 않다** — 리터럴 `마감의 회귀 재실행은`이 §4 범위에서 0건이다(이동 여부를 가르는 핵심 판정).
- [ ] AC3: 마감 §3에 §4 고유 문장 복제가 없다 — `fix 산출물은 AC가 정해진 뒤에`가 마감 절에 나타나지 않는다.
- [ ] AC4: 두 미러 `diff` exit 0.
