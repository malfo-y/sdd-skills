# Worker 공통 경계

`sdd-orchestrator`가 띄운 모든 worker가 자기 단계 계약과 함께 따른다.

- 사용자에게 질문하지 않는다. 필요한 결정은 합당한 해석으로 내리고 반환에 적는다. 진행할 수 없으면 BLOCKED와 사유를 반환한다.
- git 쓰기(commit·add·stash·checkout·reset 등)를 하지 않는다.
- 계약과 입력이 정한 대상 밖의 파일을 수정하지 않는다. 입력에 적힌, 동시에 실행 중인 다른 worker의 Target Files도 건드리지 않는다. 필요하면 수정하지 않고 반환에 적는다.
- state.md와 digest를 쓰지 않는다. 리뷰 worker(plan-review·implementation-review·simplicity)는 state.md를 읽지도 않는다.
- 다른 worker를 띄우지 않는다.
- 반환: 계약의 `반환` 형식을 따르고, 끝에 `digest 변경분` 블록을 붙인다(없으면 "없음"). 계약이 요구하는 항목만 짧게 쓴다 — 진행 서술과 요약은 쓰지 않는다.

## digest 내용 계약

메인 루프의 digest.md와 모든 worker의 반환 끝 `digest 변경분`에 같은 규칙을 적용한다. 내용 계약은 이 절이 단일 소스다.

- 허용: 이번 작업에 필요하고, 없으면 다음 worker가 비싼 재조사를 하거나 잘못 판단할 결정·제약, 환경 함정, 검증 레시피. 출처는 draft·discussion 포인터로 둔다. draft·공통 계약과 겹치는 요약은 참조로 줄이되 판단에 필요한 핵심 조건은 남긴다. 현재 유효한 내용만 남기고 바뀐 결정은 고쳐 쓴다.
- 검증 레시피: AC → 명령·입력 → 기대값. 계획의 제안은 구현·검증에서 실제 사용한 명령·입력·기대값으로 보완한다. 일상적인 digest 생성·갱신은 해당 작업에서 얻은 명령을 재사용하며, digest 작성만을 위한 추가 조사·실행·스크립트 생성은 하지 않는다. 기존 검사 호출이나 짧은 명령을 쓰고, 의미 판단은 정확한 rubric 참조를 허용한다.
- 환경 함정: 조건 → 문제 → 사용법을 짧게 적고, `_sdd/env.md`에서는 이번 작업에 필요한 항목만 전달한다. 좁은 관측을 모든 환경의 사실로 일반화하지 않는다.
- 제외: 상태·완료/통과 주장·진행/다음 조치·이력·파일 내용 복사·위치 목록·일회성 입력(fix할 findings·task 한정 지시). 상태와 실행 증거는 반환 본문의 해당 항목으로 보내 메인 루프가 state에 기록하게 하고, 일회성 입력은 dispatch 입력으로만 주고받는다.
- 예: 계측 명령과 기대 exit code는 검증 레시피다. "Task 완료", "검사 통과", "다음은 spec-sync"는 state 정보다. 허용되는 변경분이 없으면 `digest 변경분: 없음`으로 반환한다.
