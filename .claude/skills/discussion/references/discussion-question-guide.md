# Discussion Question Examples

질문 표현이 필요할 때 참고하는 예시다. 적용 여부와 질문·조사·종료 기준은 SKILL.md가 소유한다. 아래 항목을 순서대로 묻거나 모두 다룰 필요는 없다. 이미 받은 정보는 재사용한다.

| 필요한 정보 | 질문 예시 |
|---|---|
| 결정의 목적 | “이번 논의가 끝나면 무엇을 선택하거나 알 수 있어야 하나요?” |
| 중요한 제약 | “두 안의 선택을 바꿀 만큼 중요한 제약이 있나요?” |
| 사용자 우선순위 | “복구 속도와 운영 비용이 충돌하면 어느 쪽을 우선하나요?” |
| 가정의 수용 여부 | “이 안은 하루 중단을 감수해야 합니다. 허용 가능한가요?” |
| 공동 의사결정 | “세 프로젝트를 어떤 공통 기준으로 우선순위 매길까요?” |
| 의존하는 결정 | “보관 기간이 정해져야 용량을 계산할 수 있습니다. 필요한 보관 기간은 얼마인가요?” |
| 진행이 어려운 논의 | “현재 남은 차이는 측정으로 확인해야 합니다. 측정 항목을 기록하고 정리할까요?” |

설계 논점에서는 책임 경계·인터페이스·의존성·변경 영향을 살펴보는 질문이 도움이 될 수 있다. 예를 들어 “이 변경으로 기존 소비자의 동작이 달라지나요?”를 고려한다. 코드나 문서로 확인 가능한 내용이라면 먼저 확인하고, 사용자에게는 확인 결과와 남은 판단을 설명한다.

선택형 질문은 선택 결과가 분명한 문구로 구성한다. 예:

```text
질문: “복구 시간을 측정한 뒤 결정할지, 지금 목표를 조정할지 선택이 필요합니다.”
1. “실측 후 판단” — 현재 목표를 유지하고 복구 측정을 다음 작업으로 남긴다.
2. “목표 재검토” — 허용 가능한 복구 시간부터 더 논의한다.
3. “정리/종료” — 현재 결정과 미결을 저장한다.
```

의견 차이가 없는 상황에 억지로 위 선택지를 적용하지 않는다. 실제 도구·옵션 제한과 종료 처리는 SKILL.md의 Runtime 및 정리와 종료를 따른다.
